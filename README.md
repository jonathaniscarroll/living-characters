# Living Characters

A GPS + proximity virtual world builder where **characters replace locations as the primary unit**. Built from the same spatial logic as [`spatial-narrative`](https://github.com/jonathaniscarroll/spatial-narrative) — but organised around *who* rather than *where*.

---

## Architecture

```
living-characters/
  index.html               ← root redirect / entry (dev)
  author/
    index.html             ← full authoring tool (map, rooms, characters, GPS)
  story/
    StoryData.twee         ← Twine StoryTitle + StoryData passages
    rooms.twee             ← [room] tagged passages with @room lat,lng @radius
    characters.twee        ← [char] tagged passages with dialogue trees
    main.twee              ← any additional passages (optional)
  vendor/
    tweego/
      tweego               ← Tweego binary (Linux amd64, committed for CI)
    storyformats/
      sugarcube-2/
        format.js          ← SugarCube 2 story format (committed for CI)
  scripts/
    vendor-setup.sh        ← one-time setup: downloads Tweego + SugarCube
  build/                   ← generated by CI (gitignored)
    index.html             ← compiled Twine story
    author/                ← authoring tool, copied from author/
  .github/
    workflows/
      build-and-deploy.yml ← Build and Deploy Twine (mirrors spatial-narrative)
```

---

## The through-line: `spatial-narrative` → `living-characters`

`spatial-narrative` shows one passage at a time based on where you are physically, with a live compass pointing toward other unvisited nodes.

`living-characters` is the same idea but **characters replace locations as the primary unit.** Tap a character on a shared map to open their card and interact with their dialogue tree. Rooms live at real GPS coordinates — enter a room's radius and its character stage opens automatically.

---

## Build pipeline (mirrors spatial-narrative)

On every push to `main`, GitHub Actions:

1. Checks out the repo
2. Verifies `vendor/tweego/tweego` and `vendor/storyformats/sugarcube-2/format.js`
3. Compiles `story/` → `build/index.html` using Tweego + SugarCube 2
4. Copies `author/` → `build/author/`
5. Deploys `build/` to GitHub Pages

Published site:
- `/` — compiled Twine story (playable, linkable)
- `/author/` — live authoring tool (map, GPS, character editor)

---

## First-time vendor setup

The Tweego binary and SugarCube format must be committed into `vendor/` for CI to work.

```bash
bash scripts/vendor-setup.sh
git add vendor/
git commit -m 'vendor: add Tweego + SugarCube 2'
git push
```

See `vendor/tweego/TWEEGO.md` and `vendor/storyformats/sugarcube-2/FORMAT.md` for details.

## Twee passage conventions

### Rooms
```twee
:: RoomName [room]
@room lat,lng
@radius 30
@lede Short description shown on entry.

[[CharacterName]]
```

### Characters
```twee
:: CharacterName [char]
@room RoomName
@mood Happy
@items item one, item two

[[👋 Hello->CharacterName-hello]]
[[❓ Question->CharacterName-question]]
[[🤫 Secret->CharacterName-secret]]
[[😮 Reaction->CharacterName-reaction]]
[[🎒 Item->CharacterName-item-item-one]]

:: CharacterName-hello
What they say when you first meet them.

[[← Back->CharacterName]]
```

## Key constraints

- No individual computers for participants — facilitator input only
- Felt and clay as physical medium; photogrammetric scanning supported
- Mixamo GIF animations in character cards
- Structured workshops ~1 hour
- Runs in any modern browser, no install, no backend
- Thursday is always beach day 🏖️
