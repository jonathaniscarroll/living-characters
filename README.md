# Living Characters

A GPS + proximity virtual world builder where **characters replace locations as the primary unit**. Built from the same spatial logic as [`spatial-narrative`](https://github.com/jonathaniscarroll/spatial-narrative) — but organised around *who* rather than *where*.

---

## Architecture

```
living-characters/
  index.html               ← single-file tool (map + Three.js room + character editor)
  story/
    StoryData.twee         ← Twine StoryTitle + StoryData passages
    rooms.twee             ← [room] tagged passages with @room lat,lng @radius
    characters.twee        ← [char] tagged passages with dialogue trees
    main.twee              ← StoryInterface, Stylesheet, JavaScript
  media/                   ← character assets (GLB scans, GIFs, photos)
  vendor/
    tweego/
      tweego               ← Tweego binary (Linux x64, committed for CI)
    storyformats/
      sugarcube-2/
        format.js          ← SugarCube 2 story format (committed for CI)
  scripts/
    vendor-setup.sh        ← one-time setup: downloads Tweego + SugarCube
  build/                   ← generated by CI (gitignored)
    index.html             ← compiled Twine story
  .github/
    workflows/
      build-and-deploy.yml ← Build and Deploy Twine (mirrors spatial-narrative)
```

---

## The through-line: `spatial-narrative` → `living-characters`

`spatial-narrative` shows one passage at a time based on where you are physically, with a live compass pointing toward other unvisited nodes.

`living-characters` is the same idea but **characters replace locations as the primary unit.** Tap a character on a shared map to open their card and interact with their dialogue tree. Rooms live at real GPS coordinates — enter a room’s radius and its character stage opens automatically.

## Room view: Three.js isometric scene

When a room is entered (by GPS proximity or map tap) the room view renders a **Three.js scene** rather than a flat CSS canvas:

| Element | Details |
|---|---|
| Camera | `OrthographicCamera` at `(10,10,10)` looking at origin — true 45° isometric |
| Floor | `PlaneGeometry(10×10)` with a 2-colour checker texture tinted from `backdrop` |
| Walls | Two back-wall planes meeting at a corner, slightly darker than the floor |
| Character sprites | `PlaneGeometry` billboard with `photoData` or mood-emoji canvas texture; quaternion-copied from camera each frame so they always face the viewer |
| Mood rings | `RingGeometry` on the floor beneath each character, coloured by mood |
| GLB models | If a character has a `.glb` URL, `GLTFLoader` loads it, auto-scales to ~1.8 units, and plays all embedded `AnimationMixer` clips |
| Name labels | HTML `<div>` elements projected into 2-D screen space each frame |
| Click detection | `Raycaster` — clicking a sprite or GLB opens the character card |
| Resize | `ResizeObserver` keeps renderer and camera frustum in sync |

Backdrop colours per room style:

| Backdrop | Floor hex | Sky hex |
|---|---|---|
| forest | `#1a3d1a` | `#0d1e0d` |
| stone | `#2e2e3a` | `#1e1e2a` |
| water | `#0d3a5c` | `#061e36` |
| wood | `#4a2e10` | `#2a1a08` |
| grass | `#2a5a1a` | `#0e2a0e` |
| dark | `#120820` | `#0d0516` |

## Build pipeline (mirrors spatial-narrative)

On every push to `main`, GitHub Actions:

1. Checks out the repo
2. Verifies `vendor/tweego/tweego` and `vendor/storyformats/sugarcube-2/format.js`
3. Compiles `story/` → `build/index.html` using Tweego + SugarCube 2
4. Deploys `build/` to GitHub Pages

---

## First-time vendor setup

```bash
bash scripts/vendor-setup.sh
git add vendor/
git commit -m 'vendor: add Tweego + SugarCube 2'
git push
```

## Twee passage conventions

### Rooms
```twee
:: RoomName [room]
@room lat,lng
@radius 30
@lede Short description shown on entry.

[[CharacterName]]
```

### Characters

```twee
:: CharacterName [char]
@room RoomName
@mood Happy
@items item one, item two
@glb   https://example.com/media/charactername.glb
@gif   charactername-wave.gif
@image charactername.png

[[👋 Hello->CharacterName-hello]]
[[❓ Question->CharacterName-question]]
[[🤫 Secret->CharacterName-secret]]
[[😮 Reaction->CharacterName-reaction]]
[[🎒 Item->CharacterName-item-item-one]]

:: CharacterName-hello
What they say when you first meet them.

[[← Back->CharacterName]]
```

### Portrait / model asset priority

| Priority | Directive | Asset | How to make it |
|---|---|---|---|
| 1 | `@glb <url>` | Photogrammetric scan — rendered in Three.js scene | Polycam / Scaniverse → export GLB, host in `media/` |
| 2 | `@gif <file>` | Mixamo animation billboard | Mixamo → FBX → GIF via ezgif or ffmpeg |
| 3 | `@image <file>` | Static photo billboard | Any camera |
| 4 | *(none)* | Mood-emoji canvas fallback | Automatic |

All assets go in `media/` and are committed alongside `.twee` source.

## Key constraints

- No individual computers for participants — facilitator input only
- Felt and clay as physical medium; photogrammetric scanning supported
- Mixamo GIF animations as billboards in the Three.js scene
- Structured workshops ~1 hour
- Runs in any modern browser, no install, no backend
- Thursday is always beach day 🏖️
